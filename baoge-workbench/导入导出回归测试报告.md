## 四、覆盖的边界场景

- 空数据（0 条）：导出仅告警不阻断，导入后依然为空
- 超长字段：单字段最长 20000 字符的中英日韩 emoji 混合串
- 特殊字符：双引号、反斜杠、换行/制表/回车、JSON 结构字符、HTML、SQL 片段、百分号
- 多语言：简中 / 日文 / 韩文 / 阿拉伯 RTL / 俄文 / 泰文 / 印地文 / 希伯来 RTL / 繁中
- emoji：ZWJ 组合序列（家庭、彩虹旗）、肤色修饰符、基本区字符
- 控制字符：U+0000 / U+0001 / U+001F
- 代理对边界：手写 U+D83D U+DE00 组合
- 超大文件：2000 条 × 4KB 长字段，落盘约 13.15 MB
- 非法格式：非对象元素、类型错误、越界数值、非法枚举、重复 _id、缺失必填

## 五、发现的问题与修复情况

本轮共发现 4 个问题（产品代码 1 个、测试脚本 3 个），均已修复并重新验证通过：

### 1. 【测试脚本】边界注入误选枚举字段，造成「源 != 导出」假阳性

- **现象/根因**：超长字段与多语言哨兵注入时，把 progressType 等枚举字段写成了随机长字符串，校验层按 ENUM_INVALID 正确纠正为 percent，却被比对判为数据差异。
- **修复**：注入目标池排除所有带 enum 约束的字段。

### 2. 【测试脚本】注入目标池退化成 _id，造成主键重复假阳性

- **现象/根因**：body 等表没有非枚举字符串字段，注入池只剩 _id；而哨兵值在多行间重复，导致同表 _id 撞车被重新生成（如 body[409] 韩语哨兵 -> 新 id）。
- **修复**：注入目标池排除 _id；多语言哨兵改写入自由字段 x_sentinel。

### 3. 【测试脚本】脏数据构造把 _id 污染成数字，误判「合法记录未存活」

- **现象/根因**：类型污染循环未跳过 _id，把 t2._id 置为数字 777，校验层判 ID_INVALID 后重新生成，导致断言的原 _id 找不到。
- **修复**：脏字段循环显式跳过 _id，_id 只用于单独构造「重复」场景。

### 4. 【产品代码】超大备份无体积预警，解析失败提示会误导用户（实测 13.15 MB）

- **现象/根因**：2000 条长字段即可让快照达到 13.15 MB。小程序 JS 引擎解析十几 MB JSON 易卡顿或失败，而原实现失败时只提示「不是有效的 JSON 备份文件」，用户会误判为数据损坏。
- **修复**：新增 bytesOf/humanSize 与 5MB 阈值：导出超阈值写 SNAPSHOT_TOO_LARGE 日志并在 warnings 中明确提示；导入解析失败时若体积超阈值，提示改为指向「文件过大，请清理部分历史记录后重新导出」。

> 说明：上述 3 个测试脚本缺陷属于「测试数据生成器自身违反字段规格」造成的假阳性，产品校验层的行为（修正枚举、重建重复主键）本身是正确的；修复后全部轮次差异归零。

### 历史已修复项（本次回归验证仍然有效）

1. **UTF-8 BOM / 首尾空白导致整份备份无法恢复**：导入走裸 `JSON.parse`，遇 BOM 抛 SyntaxError。
   修复：新增 `parseSnapshotText()` 剥离 BOM 与空白后再解析，导入/剪贴板两条通道统一走它。
2. **健身自定义模板未纳入备份**：`DATA_KEYS` 漏了 `templates`。修复：补齐为 9 个业务表。
3. **单条脏数据会毁掉整批导入**：原实现无记录级校验。修复：新增 `backupGuard.js`，能修就修、修不了才跳过并汇总。
4. **导入写一半失败会留半截状态**：修复：写入前留存旧值，写后逐表读回校验，失败自动回滚。
5. **导出文件可能不完整**：修复：序列化后自检 + 写文件重试 3 次且每次读回比对，失败降级剪贴板。
