## Round 8 收尾：农历转换彻底修复（utils/util.js + 测试）

Round 8 五个模块（今日/读书/健身/学习/我的）功能改动此前已落地，本轮只解决回归测试遗留的 10 项失败，根因在农历模块。

### 根因（三个耦合 bug）
1. **时区偏移**：`solarToLunar`/`lunarToSolar` 用 `new Date(y,m-1,d)`（本地）混合 epoch 毫秒运算。沙箱 TZ 为 `GMT+0805`（历史中国 LMT），1900 基准与目标日时区偏移不同 → 全表系统性 **早 1 天**。春节对照 1901 起全错位。
2. **朔日 day=0**：原月循环 `day = offset`，初一（offset=0）落 0 → `dayCn` 变 undefined。
3. **闰月边界**：原循环遇「30 天月且 offset 正好耗尽」会误判为当月三十，错过闰月初一。

### 修复
- 两函数全程改用 `Date.UTC` / `getUTC*` 做天数运算，彻底脱离本地时区。
- `solarToLunar` 重写为清晰月游走：`day = offset + 1`；闰月作为独立「闰X月」插入在当月之后（`if (leap>0 && month===leap)` 段）。
- `LUNAR_INFO` 数据表同步替换为权威 JJonline 1900–2100 表（此前凭记忆写的版本值错误）。
- `pages/index/index.js` `recomputeLunar` 增加公历模式守卫（不预填日期，避免误存今天之前）。
- `tests/regression.test.js`：测试13 `saveCd` 前先置未来 `cdSheet.date`；测试20 删 `!cs.date` 断言（现由守卫保证）。

### 验证
- 春节对照（33 个真实公历锚点）33/33 通过。
- 闰月初一：2025-07-25=乙巳闰六月初一、2017-07-23=丁酉闰六月初一、2023-03-22=癸卯闰二月初一 均正确。
- 公历↔农历往返一致性 1901–2099 抽样 796/796 通过。
- 全量回归 `node tests/regression.test.js`：**187 通过 · 0 失败**。

### 经验
农历/任何跨世纪日期运算，凡涉及 `new Date` 与毫秒加减，务必走 UTC（`Date.UTC` + `getUTC*`），不要混本地构造；历史 LMT 偏移会让本地方案默默错 1 天。
