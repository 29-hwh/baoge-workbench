# 板块升级优化建议 · 读书

> 版本基线：v0.5（三单位进度 + 读了一节 + 想法时间线 + 目标日 + 周报 + 读完打分书评 + 书脊墙打星 + md 导出）
> 定位：纸书阅读的管理与"读完的仪式感"——书脊墙是差异化资产。
> 本文只谈「读书」Tab；与首页派生的关联不在本篇展开。

---

## 一、当前已实现（盘点）

- **加书流程**：书名/作者 → 进度单位（章/页/百分比）→ 总量，三步走
- **进度记录**：读了一节 +1（零面板即时步进）、定位滑块快速跳章/页/百分比
- **产出层**：想法随手记（落 records 按书归档）、目标读完日（逾期标红）、阅读习惯周报
- **读完仪式**：读完 → 选日期（今天/昨天/补记过去）→ 选星 → 一句话书评 → 上书脊墙
- **书脊墙**：打星、长按详情卡（评分/书评/想法归档/历时天数）、可改星改评
- **导出**：读书笔记 Markdown 发文件助手 / 复制全文
- **性能**：仅展开的书才排序构建时间线（限 50 条），避免卡顿

---

## 二、做得好的（保留）

- **三单位进度**颗粒感强，章/页/百分比覆盖不同读书习惯
- **书脊墙 = Bookly 收集墙的纸书版**，是竞品没有的差异化
- 读完动线（日期→星→评→上墙）一气呵成，有仪式感

## 三、升级建议（按优先级）

| 优先级 | 建议 | 具体做法 | 价值 | 工作量 |
|---|---|---|---|---|
| **P0** | 加书流程合并 | 把"书名作者→单位→总量"三步合成**单表单弹层**（书名/作者/单位选择器/总量一行搞定） | 小白加书少点 2 次，摩擦骤降 | 中 |
| **P0** | 阅读计时 | 记录"本次阅读时长"，估算每日/每周阅读分钟数，周报加一列 | 阅读也是"投入"，值得被量化 | 中 |
| **P0** | 书卡视觉增强 | 在读卡片用封面（可选）/ 色块书脊 + 进度弧，向书脊墙视觉靠拢 | 书架更像"书架"，不是列表 | 中 |
| **P1** | 目标日提醒打通首页 | 临近/逾期目标日，在首页待办或概览给轻提示 | 让"目标"从摆设变约束 | 小 |
| **P1** | 书评富化 | 书评支持多行 + 标签（如#工具书 #小说），书脊墙可按评分/读完时间筛选排序 | 读过的书更好回看与管理 | 中 |
| **P1** | 搜索/筛选 | 书多时按作者/状态/评分过滤 | 书架变厚后必需要 | 小 |
| **P2** | 月度/年度阅读报告 | 本月几本、总页数、笔记数、平均评分、最长连读 | 把"读了多少"变成可炫耀的成长 | 中 |
| **P2** | 书单导入 | 手动输 ISBN/从豆瓣抓书名作者（需注意合规与 API 成本） | 批量加书省事 | 大（含外部依赖） |
| **P2** | 读书↔学习打通 | 读完一本书可关联"学习"里某个技能阶段达成 | 让三模块真正互相喂养 | 大 |

## 四、权衡与注意

- **别做成电子书阅读器**：你记的是纸书，不接书封 API、不 OCR（中文书封无合规免费源）。封面可让用户自选本地图，或继续用色块书脊。
- **加书流程别过度简化到丢信息**：合并表单时仍要保留"单位 + 总量"两个关键字段，否则进度无法计算。
- **阅读计时默认关闭更稳**：自动计时可能误记（翻看不读），建议"手动开始/结束"或"记一笔时顺带记时长"，避免数据失真。

---

## 五、建议落地顺序

1. **P0 加书合并 + 书卡视觉** 优先——这是用户每天都会碰的高频操作。
2. **P0 阅读计时** 紧随，补全"投入量化"缺口。
3. P1/P2 看真实藏书量再排，书少时搜索/报告优先级可降。
