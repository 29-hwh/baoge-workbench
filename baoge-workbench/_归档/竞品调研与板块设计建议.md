# 宝哥工作台 · 竞品调研与板块设计建议

> 版本：v1.0 ｜ 日期：2026-09-03
> 说明：本文件整合两轮全网竞品调研结论 + 四大板块设计建议 + 一次关键 bug 修复记录。
> 文档定位：后续每个板块细化、评审、对需求时的**对照依据**。

## 一、一句话定位（产品魂）

宝哥工作台**不是又一个待办/打卡 App**，而是一个**「计划驱动的个人成长引擎」**：

> **计划（读书/技能/健身）→ 派生今日待办 → 完成 → 沉淀成书脊墙 / 技能图鉴**

- 首页永远是「今日待办」执行台
- 核心差异化：**多模块打通 + 越攒越有的堆叠成就感**
- 价值观：**宽容型记录**（进度永不算断），区别于所有"断签焦虑型"打卡 App

---

## 二、市场格局与你的空白位

### 2.1 竞品定位象限

用两个轴划分现有产品：
- **横轴 = 记录深度**（浅：只管"做没做"；深：记录过程数据）
- **纵轴 = 单模块还是多模块**

| 类别 | 代表 | 深度 | 覆盖 | 最大软肋 |
|---|---|---|---|---|
| 打卡/习惯 | 小日常、习惯清单 | 浅 | 通用 | 只记"做没做"，读了几章它不知道 |
| 专业读书记录 | 微信读书、Bookly | 深 | 仅读书 | 只读书，且微信读书锁电子书 |
| 专业健身 | Strong、Hevy、训记 | 深 | 仅健身 | 功能专业但重，个人用不上全套 |
| All-in-One | Notion、飞书多维表格 | 深 | 全 | 要自己搭，且**没有成就感设计** |
| **你要做的** | 宝哥工作台 | 中 | 读书+健身+技能+代办 | —— |

### 2.2 关键结论

> **右上角空白真实存在：没有任何一个产品同时做到「开箱即用 + 多模块打通 + 成长可视化」。**

- 打卡类轻但浅；专业类深但散（要装四个 App，数据互不相通）
- Notion 全能但无成就感层，且学习成本高
- 这个空白存在的原因：四块单做商业价值都不够（大厂不做），做全又难（个人做不全）
- **所以它天然是"自己用最香"的产品**，不必追求大众市场爆款

## 三、四大板块：抄谁 · 抄什么 · 避开什么

### 板块 1 · 读书
- **抄谁**：微信读书（进度颗粒感）+ Bookly（读完的收集墙）
- **抄什么**：
  - 进度以"章"为单位，颗粒可见、可勾选
  - 读完那一刻有**仪式感反馈**（区别于普通打勾）
  - 你的**书脊墙 = Bookly 收集墙的纸书版**，是差异化
- **避开**：
  - ✗ 不做成完整阅读器（你记的是纸书，不是读电子书）
  - ✗ 不接书封 API、不做 OCR（中文书封无合规免费源，手输书名 + 色块书脊即可）
  - ✗ 书单页别堆太多列，核心只有"在读 / 读完"两态

### 板块 2 · 今日代办 / 打卡
- **抄谁**：小日常 / 习惯清单（打卡的轻交互、完成动效）
- **抄什么**：
  - 完成即打勾的爽快感
  - 连续天数的小激励（鼓励式，非惩罚式）
  - **你的差异化**：代办挂靠计划（读书/技能/健身）自动派生，不是孤立清单
- **避开**：
  - ✗ 不做番茄钟/专注计时等发散功能
  - ✗ 不做"缺一天就断"的焦虑压力——**你是宽容型**
  - ✗ 首页别堆日历格子，让"今天做什么"一眼可见

### 板块 3 · 健身
- **抄谁**：Strong / Hevy / 训记（动作级记录：组数+次数+重量）
- **抄什么**：
  - 一次训练 = 一组动作列表，每组填重量 × 次数
  - 练完自动算该动作总量
  - **关键打通**：练完一键勾掉首页当日训练代办
- **避开**：
  - ✗ 不做内置动作库/组间计时/热身编排（专业但重，个人用不上）
  - ✗ 不接手环/健康数据（MVP 数据源越少越好）
  - ✗ 别按"身体部位"造复杂层级，粒度 = 一次记录就够

### 板块 4 · 学习 / 技能
- **抄谁**：Notion 目标库 / 技能树 App（技能→阶段→点亮）
- **抄什么**：
  - 目标拆成可勾选的阶段清单，进度可量化
  - **你的差异化**：达成技能变徽章进图鉴（Notion 没有成就感层）
- **避开**：
  - ✗ 阶段别设成"每天打卡 N 小时"这类不可量化目标
  - ✗ 别做技能等级/经验值那种游戏化虚标
  - ✗ 技能图标手输 emoji 就够，不引图标库加重包体

## 四、打通三模块到首页待办（核心架构）

### 4.1 设计原则

你强调的"健身/读书/技能里的待办都要和主页今日代办关联"——这就是**派生引擎**。核心机制：

```
在读书页 +1 章 / 技能页点亮阶段 / 健身页建训练
        ↓ 切回首页 onShow 自动派生
首页出现对应待办（带来源标记 + 回写锚点）
        ↓ 点完成
反向回写：读书章节+1、技能阶段点亮、训练标记完成
        ↓ 推进到终点
书脊墙 / 技能图鉴自动收录
```

### 4.2 三条关联规则

| 模块 | 派生条件 | 完成回写 |
|---|---|---|
| **读书** | 在读且未读完的书 → 派生「继续读《xxx》」 | 当前章节 +1；到末章自动推进书脊墙 |
| **学习** | 未达成的技能 → 取最近未完成阶段 → 派生 | 该阶段点亮；全阶段达成 → 徽章进图鉴 |
| **健身** | 当天有训练记录且未完成 → 派生 | 训练标记完成；若直接完成可一键全动作标完 |
| **手动** | 不参与派生，仅显示 | 仅切完成态 |

### 4.3 关键 Bug 修复记录（本次）

**问题**：存储层 API 签名是 `storage.xxx(logicalKey)`（内部再查 `KEYS[logicalKey]`），但**五个页面误传了 `storage.KEYS.xxx`（即原始 key 的值 `baoge:xxx`）**，导致 `KEYS['baoge:xxx'] = undefined` → 写入/读取落到错误槽位。

**后果**：读书/学习/健身页新增的数据存错位置，首页派生引擎读 `storage.list('books'/'skills'/'workouts')` 拿到空数组 → **三模块待办一条都派生不出来**（正是"无法关联首页"的根因）。

**修复**：全项目替换 14 处 `storage.(add|update|remove)(storage.KEYS.xxx)` → `storage.方法('xxx')`，保留正确的 `wx.setStorageSync(storage.KEYS.xxx)`（setStorageSync 本就需要原始 key 值）。

**验证**：端到端单测 11 项全绿 —— 加书/技能/训练 → 派生 3 条 → 各自完成回写均正确。

> ⚠️ 给宝哥的重要提醒：**你之前如果已经在开发者工具里"试玩"过并手动加了读书/技能数据，那批数据可能写进了错误槽位。修复后建议在「我的」页做一次"清空数据"再重新录，确保干净起点。**

## 五、下一阶段开发建议（务实路线）

1. **先真实用两周**：当前 v0.2.0 已具备三模块录入 + 首页派生回写 + 备份闭环，足够个人真实使用。让真实使用数据告诉你"哪个按钮从没点过"，比任何调研都准。
2. **MVP 不贪**：书脊墙 / 技能图鉴已能由数据自动驱动；复杂动画、成就周报、分享卡片放二期。
3. **表单体验升级**：现在多处用 `showModal + editable`，交互较糙，后续换成正经弹层表单。
4. **备份已闭环**（v0.2.0）：用微信 `shareFileMessage` + `chooseMessageFile`，无需服务器即可"发到电脑看 / 换机恢复"。
