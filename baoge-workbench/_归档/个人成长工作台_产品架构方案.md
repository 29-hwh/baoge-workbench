# 宝哥工作台 · 微信小程序产品架构方案

> **小程序名**：宝哥工作台
> **定位**：一款 **个人自用的成长管理系统**，将「代办执行」与「读书/健身/学习三大计划」结合，
> 以 **书脊墙 + 技能图鉴** 的可视化沉淀，给使用者持续的成就感与复利反馈。
> 本文档用于需求对齐、开发评审与后续迭代参照。

**版本：v0.2（2026-09-03 决策更新）**
更新内容：命名确定、健身模块保留、取消拍照识别、书封方案调研、云开发额度按新计费规则重算。

---

## 一、产品定位一句话

> **不是记账本，而是一个"计划驱动的成长引擎"。**
> 计划（读书/技能/健身）→ 派生今日待办 → 完成 → 沉淀为成就墙。

首页永远是「执行入口」，背后挂载「计划」；读完的书堆成书脊墙，达成的技能收进图鉴。

---

## 二、信息架构（Tab 式主导航）

```
底部 TabBar（5 主入口，全部保留）
├─ 首页·今日      ← 核心执行层：今日待办 + 三模块进度速览
├─ 读书 📚        ← 书架（在读）→ 读完推入书墙（已读）
├─ 健身 🏋        ← 训练计划 + 动作/组数/重量细记录
├─ 学习 🎯        ← 技能进度 + 达成后收进技能图鉴
└─ 我的 👤        ← 成就总览 / 统计 / 设置
```

**跨模块通用组件：**
- 手动建书（书名 / 作者 / 总章节数 / 颜色）
- 技能目标设定弹层（命名 → 定目标 → 拆阶段）
- 「计划 → 任务派生引擎」（把读书章节 / 技能课时 / 健身动作派到今日）
- 成就分享卡片（用于传播获客）

## 三、四大核心页面视觉方案

### 1. 首页·今日（执行台）
- 顶部问候 + 日期
- **今日待办列表**：每项带「来源标记」，区分三种来源
  - 📝 手动随手记（杂事，可打"重要"标签）
  - 📖 来自读书计划（自动派生章节任务）
  - 🎯 来自技能学习（自动派生课时）
  - 🏋 来自健身计划（自动派生训练动作）
- 底部**本周成长速览**：读书/健身/学习三个迷你进度卡
- 核心原则：一眼看到「今天干什么 + 成长走到哪」

### 2. 读书页（书架 + 书墙双视图）
- **书架（在读）**：横向卡片，每本显示阅读进度条（如 12/28 章）
  - **纯手动建书**（不做拍照识别 / OCR）
  - 点入可看章节列表、读书记录、一键标记读完
- **书墙（已读·成就）**：木纹暖色背景，每一本读完的书"立"成一本书脊
  - 书越多墙越满，是核心成就感画面
  - 可横屏 / 翻页看大图，支持生成分享图
- 交互原则：读完一本书 → 从书架"推入"书墙

### 3. 学习页（技能线 + 图鉴）
- **技能学习卡**：每个技能 = 一条学习线
  - 名称 + 图标 + **可衡量目标** + 进度条 + 剩余预估
  - 阶段可含课时/练习，进度条 = 阶段点亮数
- **技能图鉴（成就）**：达成后的技能变成徽章格子，收集进图鉴，像集卡
- 新增技能弹层：选图标 → 命名 → 定目标（可衡量成果）→ 拆阶段 → 计划节奏 → 开始
- 关键规则：**目标必须"可衡量、有终点"**，全部阶段点亮 = 达成 = 徽章进图鉴

### 4. 健身页（训练记录单）
- 训练计划卡片（如「胸+三头·推日」），进度状态标签
- **动作级细记录**：每个动作 → 多组 → 每组填「次数 + 重量」
  - 常用动作库快捷选
  - 历史重量自动建议（递增负载）
- 练完自动把「今日训练待办」勾选为完成，与首页联动

## 四、数据模型草案（MVP一期）

```
plans          书 / 技能 / 训练计划的元信息
tasks          可派生的待办任务（读书章节 / 技能课时 / 动作组）
records        每日完成记录 & 健身组数明细
achievements   完成后沉淀的成就（书脊 / 技能徽章）
profile        用户设置 / 目标总览
```

**关系主线：**
```
计划(plan) ──生成──▶ 待办(task) ──完成──▶ 记录(record) ──达成──▶ 成就(achievement)
读书读毕 → 书脊进书墙；技能达标 → 徽章进图鉴
```

## 五、技术选型（微信云开发）

```
┌────────────────┐        ┌────────────────┐        ┌──────────┐
│  小程序前端     │  ◀──▶  │  微信云开发      │  ◀──▶  │  数据层    │
│  WXML/WXSS/JS  │        │  云函数          │        │ 云数据库  │
│  TDesign 组件  │        │ 业务逻辑 · 鉴权   │        │ 云存储    │
│  本地缓存加速   │        │ 成就派生引擎      │        │ (可选图)  │
└────────────────┘        └────────────────┘        └──────────┘
```

**为什么选云开发（而非自建服务器）：**
- 免维护服务器、免域名备案、免 HTTPS 配置 —— 个人项目最省心
- `wx.login` 天然打通微信身份，无需自己做注册/登录
- 支持手机 + 电脑网页端查看
- 后续想扩大可平滑迁移 / 二次开发

### 成本实测（重要：计费规则已改为「资源点」）

CloudBase 现按**资源点**统一计量（1,000 点 ≈ ¥1），不再是旧的"5GB + 5万次/天"固定额度。

| 计费项 | 单价 | 个人自用月估 | 消耗 |
|---|---|---|---|
| 数据库调用 | 200 点/万次 | ~3,000 次 | ~60 点 |
| 云函数调用 | 13.3 点/万次 | ~3,000 次 | ~4 点 |
| 云存储容量 | 3.94 点/GB·天 | ~0.5 GB | ~59 点 |
| **合计** | | | **≈ 120 点/月** |

**套餐对照：**
- 免费体验版：**3,000 点/月**（微信入口新用户首期 40,000 点，体验 6 个月）
- 个人版：¥19.9/月，40,000 点/月

**结论：个人自用月耗约 120 点，仅占免费额度的 ~3%，完全够用，0 成本。**
⚠️ 注意：免费环境单次续期 6 个月，到期前 1 个月内记得续期，否则环境会被回收。

**可选组件库：** TDesign 微信小程序版（60+ 组件），适合快速搭出干净界面。

## 六、书封方案（关键决策）

### 调研结论：中文书封没有靠谱的免费 API

| 方案 | 状态 | 问题 |
|---|---|---|
| **Open Library** | 免费、无需 key | 中文书覆盖率差；国外域名，需加入小程序 downloadFile 白名单，加载慢且有审核风险 |
| **豆瓣图书 API** | 已关闭（2018 起不再开放申请） | 只剩非官方抓取，违规风险高、随时可能挂 |
| **国内接口**（isbn.work / 探数 / 易源等） | 需申请 key 或按次计费 | 个人几十本书的量，性价比极低 |
| **Google Books** | — | 国内访问受限 |

### ✅ 推荐方案：色块书脊（不接任何 API）

每本书用**一个配色 + 书名文字**生成书脊，不依赖真实封面图。

**优势：**
- 零成本、零外部依赖、零合规风险
- 加载极快（不下载图片）
- 配色本身成为书墙的设计语言，视觉统一
- 与"纯手输书名"的决策一致，逻辑自洽

**可选项：** 后续若想看真实封面，可在书籍详情里**手动上传一张图**到云存储作为补充，不影响书墙主体。

## 七、视觉规范

- **主色** `#534AB7`（学习紫）+ 分类强调色
- 模块色：读书=蓝 · 健身=橙 · 学习=绿 · 今日/待办=红
- 白底卡片 + 0.5px 细边框 + 大圆角
- 文案鼓励向，进度条贯穿所有模块
- 书墙用木纹暖色质感；其余页面保持极简卡片风
