# 除小程序外，还能怎么用「宝哥工作台」

> 起因：小程序的入口链路太长 —— 打开微信 → 找到小程序 → 点进去 → 翻到对应 Tab。
> 想记一条待办，光找入口就耗掉一半耐心。
>
> 本文给出 6 种替代/补充形态，并说清各自的**数据存在哪**、**代价是什么**。

---

## 一、先看清真正的约束：问题不在界面，在数据

| 事实 | 依据 |
|---|---|
| 工作台是**纯本地**的，没有后端 | 工程内无 `server/`、无 `cloudfunctions/`，代码里没有 `wx.request` |
| 所有数据住在 `wx.setStorageSync` 里，key 前缀 `baoge:` | `utils/storage.js` 的 `KEYS` 表 |
| 数据是**微信 App 私有的**，别的程序读不到 | 小程序沙箱机制，这是平台硬约束 |
| **但你已经有导出通道了** | 「我的 → 导出备份」，产出的就是一份标准 JSON |

所以任何"换个壳"的方案，本质都要回答同一个问题：

> **数据搬到新壳之后，住哪？怎么和小程序保持一份？**

而你已经做完的**导入导出**，正好就是这座桥 —— 这是整件事的杠杆点。

---

## 二、六种形态对比

| # | 形态 | 数据住哪 | 解决什么 | 代价 | 与小程序数据互通 |
|---|---|---|---|---|---|
| 1 | **小程序本体** | 微信 `wx.setStorageSync` | 手机随身、随时随地 | 入口链路长（微信→小程序→Tab） | 基准 |
| 2 | **桌面版单文件 HTML** ⭐ | 浏览器 `localStorage`（key 同 `baoge:` 前缀） | 大屏 + 键盘 + 双击即开，录入效率高一个量级 | 需手动导出/导入做一次同步 | ✅ **备份 JSON 双向互通已验证** |
| 3 | **微信开发者工具预览** | 同小程序（模拟器沙箱） | 改代码时即时看效果、调样式 | 装 IDE、每次要编译，不适合日常使用 | 原生一致 |
| 4 | **只读数据看板** | 读导出的 JSON，不写 | 把数据变成图表（读书量趋势、体重曲线） | 只看不改 | 单向（JSON → 看板） |
| 5 | **命令行 CLI** | 直接读写备份 JSON 文件 | `wb todo 买牛奶` 一行记一笔，可脚本化/自动化 | 要开终端，有学习成本 | 双向（文件即真相） |
| 6 | **手机浏览器 / 添加到主屏** | 浏览器 `localStorage` | 手机上不经过微信也能用 | 需把 HTML 传到手机；文件型页面无法真正"添加到主屏" | 需手动导出/导入 |

## 三、本轮已交付：桌面版（方案 2）

**文件**：`个人成长工作台小程序/baoge-workbench/`

| 文件 | 作用 |
|---|---|
| `宝哥工作台_桌面版.html` | 单文件工作台本体，零依赖，双击即开 |
| `桌面版_启动.command` | 双击启动器，用 Chrome 应用模式打开（无地址栏，像原生 App） |
| `tests/desktop-interop.test.js` | 互通性验证，17 项断言 |

### 它做了什么

- **五个 Tab 全在**：今日 / 读书 / 健身 / 学习 / 我的，对应小程序的五页
- **能真正增删改查**，不是只读快照：
  - 今日：加待办、勾选完成、删除、标"重要"、按日期
  - 读书：上架、更新进度、读完自动进书脊墙
  - 健身：训练记录、身体数据（体重/体脂）
  - 学习：技能打卡、达成后进图鉴
- **备份格式与小程序逐字节一致**：`{app, version, exportedAt, counts, data, checksum}`，
  checksum 用的是同一个 FNV-1a 算法，5 组样本交叉比对完全一致
- **支持拖拽导入**：把小程序导出的 JSON 拖进"我的"页即可续用
- **暗色主题**、数据总览、示例数据一键载入

### 怎么用

```
1. 双击 桌面版_启动.command        → 打开桌面版
2. 在小程序里：「我的 → 导出备份」→ 发给文件传输助手
3. 电脑微信里把那个 .json 存到桌面
4. 桌面版「我的 → 导入备份 JSON」或直接拖进去   → 数据就搬过来了
5. 反过来同理：桌面版导出 → 微信发回 → 小程序里恢复
```

### 已验证的事实

| 验证项 | 结果 |
|---|---|
| checksum 算法一致性（5 组样本含中文/emoji/西里尔/日文） | ✅ 完全一致 |
| 小程序导出 → 桌面版导入 | ✅ 10 条全量通过，嵌套 `records` 完整 |
| 桌面版导出 → 小程序导入 | ✅ 小程序 `applySnapshotObject` 完整吃下，`checksumOk: true` |
| 篡改内容后双向识别 | ✅ 两边都报 `CHECKSUM_MISMATCH` |
| BOM / 首尾空白容错 | ✅ 双向可解析 |
| localStorage 跨进程持久化 | ✅ 关掉浏览器再打开，数据还在 |
| 浏览器冒烟（加待办/勾选/加书/示例数据/导出/换主题） | ✅ 无任何页面错误 |

## 四、方案 4 与 5：值得做，但没做（等你拍板）

这两个我没动手，因为**都属于"要不要多一个数据副本"的取舍**，得你定：

### 4. 只读数据看板

把导出的 JSON 拖进去 → 出图表：读书量月趋势、体重/体脂曲线、技能打卡热力图。

- **优点**：零风险（只读不写），视觉价值高
- **代价**：又一个文件、又一处入口
- **建议**：如果你想要"看得见成长"，值得做；如果只是嫌小程序入口长，不必

### 5. 命令行 CLI

```bash
wb todo "买牛奶"           # 往今天的待办里加一条
wb book "置身事内" 42      # 更新读书进度到 42%
wb done 3                  # 完成第 3 条
wb export > ~/backup.json  # 导出
```

- **优点**：一次录入 3 秒，可写脚本/配合定时任务；数据真相就是一个 JSON 文件，好备份好版本管理
- **代价**：要开终端；和桌面版的 `localStorage` 是**两套数据**，需要明确"谁是主"
- **建议**：如果你想把它当"个人数据仓库"来管，CLI + JSON 文件是最干净的架构；
  如果只是随手记，桌面版够了

## 五、推荐路径

| 你的诉求 | 推荐 |
|---|---|
| 手机随身记，不折腾 | 就用小程序（方案 1），入口长的问题忍了 |
| **电脑上高效录入，大屏看得清** | **桌面版（方案 2，已交付）** ← 本轮重点 |
| 想让数据看得见 | 再做只读看板（方案 4） |
| 想把数据当资产长期管 | 上 CLI + JSON 文件为唯一真相（方案 5） |
| 改代码时要看效果 | 微信开发者工具（方案 3） |

## 六、一个要提前知道的坑

桌面版的 `localStorage` 是**按浏览器配置隔离**的。所以：

- ✅ 用 `桌面版_启动.command` 打开 → 和直接双击 HTML 打开 → **看到的是同一份数据**（已刻意共用默认浏览器配置）
- ❌ 如果你把 HTML 拷到另一台电脑 / 换一个浏览器 → 数据不会跟过去，**要先导出 JSON 再拷**
- ⚠️ 清理浏览器数据（"清除浏览数据"里勾了 Cookie 和网站数据）会连带清掉工作台数据
  → **养成习惯：定期在「我的」页导出一次备份**

## 附：为什么不做 Electron / 原生 Mac App

能做得更"像 App"，但要装 Node 工具链、打包、签名、每次都重新分发，为一个自用工具是杀鸡用牛刀。
单文件 HTML + 应用模式启动器，已经拿到了 90% 的体验，维护成本接近零。
如果哪天你真的想要 Dock 图标、菜单栏入口，再上 Electron 也不迟 —— 数据层（备份 JSON）已经就绪，换壳不用重做数据。
